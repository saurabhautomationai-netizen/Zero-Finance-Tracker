Findings

Ranked by what breaks for the user, not by how hard it is to fix.

Critical

Transactions are written to Postgres, but every report reads Google Sheets

The capture chain ends at Insert Transaction against the Postgres transactions table. Nothing in that chain appends to a spreadsheet. Meanwhile the report, finance chat, forecast and affordability branches all read the Transactions sheet, and the monthly report reads Sheet1.

The consequence is that an expense logged by chat is confirmed to the user, then never appears in a single report, budget figure, forecast or chat answer. The two halves of the product are looking at different data.

FixPick one store. If Postgres is the intent, convert the nine read branches to SQL. If Sheets is the intent, add an append after Insert Transaction — or replace the Postgres node outright and keep Postgres only for user identity.
Critical

Real WhatsApp messages are received, classified, then silently dropped

The Meta webhook at /whatsapp-webhook handles verification correctly. The message branch normalizes the payload, loads conversation context, runs it through AI Agent (Intent Classifier)1 — and hands the result to Switch2, which has no outgoing connections at all.

The chain that should follow it exists and is fully built — Get All Transaction → Finance Chat Context Code → Finance Chat Agent → Build WhatsApp Reply Payload → HTTP Request — but has no inbound connection either. It was never joined up. Every real WhatsApp message costs an OpenAI call and gets no reply.

FixWire Switch2's outputs to the orphaned Finance Chat chain, or disable the webhook until that path is finished so it stops burning tokens.
Critical

Everything labelled "WhatsApp" is actually Telegram

WhatsApp Webhook is an n8n-nodes-base.telegramTrigger, and all eighteen outbound "WhatsApp …" nodes are Telegram send nodes. The shipping product is a Telegram bot wearing WhatsApp names, alongside a second, unfinished, genuinely-WhatsApp path.

This is not cosmetic. Anyone reading the canvas — including you in six months — will mis-diagnose which channel is live, and the two paths maintain separate conversation state.

FixRename the Telegram nodes to say Telegram, and decide whether WhatsApp is a second channel or a replacement. If it's a replacement, the ten intent branches need to be shared between both front doors rather than duplicated.
High

Every PDF runs down both document paths at once

PDF_Extract from File has two nodes on its single output: Document Analyzer Agent and Bank Statement Analyzer Agent. Both run for every PDF that arrives.

A one-line receipt is therefore also parsed as a bank statement, and a real statement is also pushed through the single-transaction path. Both branches can write, so a single upload can produce duplicate rows in Transactions — and it doubles the token cost of every PDF.

FixPut a switch after the extract step that decides receipt vs. statement — page count, row count, or a cheap classifier call — and send the file down exactly one branch.
High

The monthly report reads a sheet nothing writes to

Get All Rows Transactions Sheet reads Sheet1. Every append in the workflow targets Transactions, CreditCards, Loans, Subscriptions or Reminders — never Sheet1. The only other nodes touching it are two disconnected leftovers.

So the monthly report — totals, subscription detection, and the insights agent's narrative — is running on whatever historical rows happen to sit in Sheet1, not on this month's activity.

FixPoint it at Transactions (or the Postgres table, once finding 1 is settled) and re-run it manually to confirm the numbers move.
Medium

gpt-4o-mini is doing the vision and statement work

All ten agents run gpt-4o-mini. That is a sound default for intent routing and short text extraction, and it keeps the per-message cost low.

Two jobs are pushing against its limits: Vision Agent (Image) reading receipt photographs, and Bank Statement Analyzer Agent extracting many rows of tabular data. These are exactly the tasks where a weaker model silently returns plausible-but-wrong amounts, which then get written to the ledger as fact.

FixMove those two agents to a stronger model and leave the other eight on mini. The volume on those branches is low, so the cost difference is small.
Medium

Reminders fire at 02:55

Schedule Trigger_Reminder runs daily at 02:55 in the instance timezone and sends the alert immediately. Bill reminders arrive in the middle of the night, which is when they are least likely to be acted on and most likely to get the bot muted.

FixMove it to a morning hour and set the workflow timezone explicitly rather than inheriting the instance default.
Low

Debug and leftover nodes are still on the canvas

Four nodes have no connections in either direction: Execute a SQL query (a scratch SELECT NOW(); SELECT * FROM users; SELECT * FROM transactions;), Append row in sheet, Get row(s) in sheet1, and Get All Transactions Sheet.

They don't run, but they make the canvas harder to read and they're the reason Sheet1 still looks like a live target.

FixDelete them, or move them into a clearly-marked scratch area of the canvas.
Resolved

Your notes say the intent classifier is missing — it isn't

Notes.txt lists "Intent Classifier" and "conversational finance AI" as the gaps still to close. Both are built: there are two intent classifiers — one per front door — routing to ten branches, plus a working Finance Chat Agent. The example questions in that file ("How much did I spend on food?", "Which category is highest this month?") are served by intent routes 2 and 3.

The real gap is that route 2 reads a sheet the capture path never writes to, which is finding 1 — not a missing feature.

Suggested order of work

Findings 1 and 5 are the same decision, so they get made together. Everything else is independent.

First, settle the datastore question — Postgres or Sheets — and make the capture path and all nine read branches agree. Until that is done, the numbers the bot reports are not the numbers the user entered, and no other fix changes that.

Then, split the PDF fan-out, so uploads stop double-writing into whichever store you just standardized on.

Then, decide WhatsApp's fate: finish Switch2 or disable the webhook. Leaving it half-wired costs money on every inbound message and returns nothing.

Last, the housekeeping — rename the Telegram nodes, upgrade the two vision-and-statement agents, move the reminder off 02:55, and clear the four orphans.
